# 批量重命名器 交付说明

> 版本：0.06.17

## 1. 交付方案

`release/` 下提供三套交付文件，三套方案共享同一份核心与界面代码，由 `tools/build_release.py` 生成。

| 方案 | 目录 | 特点 |
|---|---|---|
| 方案1：仅重命名不执行 | `release/方案1-仅重命名不执行/` | 无执行配置、无执行按钮、无完成按钮；【生成输出】显示为【执行】；点击输出三个非跳过列表并关闭窗口 |
| 方案2：执行不输出列表 | `release/方案2-执行不输出列表/` | 无【生成输出】按钮；不生成/输出列表变量；使用【执行】完成复制/移动/重命名/删除原文件，【完成】关闭窗口 |
| 方案3：重复获取+重命名+执行 | `release/方案3-重复获取+重命名+执行/` | 与方案2相同的执行界面；支持点击【重新获取选择的文件】替换输入并连续处理多批 |

方案1没有【完成】按钮；方案2、方案3保留【完成】按钮。三套方案共享代码，由构建脚本生成。

本版（0.06.17）新增方案3与【重新获取选择的文件】：读取资源管理器选中文件并替换当前输入；选择为空时提示“未选中任何文件”；执行期间禁止重新获取。方案3标题与提示按连续多批处理展示。

## 2. 方案1：仅重命名不执行

- 窗口不显示执行配置框、【执行文件】按钮与【完成】按钮。
- 底部按钮为【取消】【执行】（原【生成输出】改名）。
- 点击【执行】生成并输出三个列表，然后关闭窗口，Quicker 继续执行后续动作步骤；不会修改文件。
- 输出：列表【原路径和文件名】、列表【目标路径和文件名】、列表【执行动作】，只包含非跳过且有有效目标路径的行，三者逐项配对。动作值可能为“复制”“移动”“重命名”“删除原文件”；后续步骤需按动作值处理。
- 预设：【批量重命名器预设】、【扩展名预设】照常保存/写回。
- 数据映射：

```text
files:{输入文件路径}
startYear:{最早起始年份}
preset:{批量重命名器预设}
extensionPresets:{扩展名预设}
origPaths:{原路径和文件名}
targetPaths:{目标路径和文件名}
actions:{执行动作}
```

- 适用：窗口只负责生成重命名/移动/复制计划，实际文件操作由后续 Quicker 步骤完成。

## 3. 方案2：执行不输出列表

- 窗口保留执行配置框与【执行】按钮。
- 不显示【生成输出】按钮；保留【完成】按钮。
- 不初始化、不写入列表变量。
- 预设：【批量重命名器预设】、【扩展名预设】照常保存/写回。
- 数据映射：

```text
files:{输入文件路径}
startYear:{最早起始年份}
preset:{批量重命名器预设}
extensionPresets:{扩展名预设}
```

- 适用：窗口内直接完成复制/移动/重命名/删除原文件，后续步骤只使用预设或不再需要路径列表。

## 4. 方案3：重复获取+重命名+执行

- 界面与方案2相同：无【生成输出】按钮，保留执行配置、【执行】与【完成】。
- 不初始化、不写入任何路径列表或动作列表变量。
- 标题显示为“批量重命名器（重复获取+重命名+执行）”，提示为“重新获取选择的文件，可连续处理多批”。
- 执行完成后窗口保持打开；回到资源管理器重新选择文件，点击【重新获取选择的文件】即可替换输入并继续下一批。
- 数据映射与方案2相同：`files`、`startYear`、`preset`、`extensionPresets`。
- 限制：选择读取依赖`Shell.Application`；Win11多标签页或第三方文件管理器可能只能读取活动标签或无法读取。文件夹、虚拟项与已不存在的路径会被忽略。

## 5. 共同行为

- 展示列表行状态使用**行背景色**表示：成功浅绿、失败浅红、计算中浅黄、跳过浅灰。
- 展示列表四列：动作、状态（含执行结果与异常信息）、源路径名、目标路径名/文件名；点击每个表头的▼可按该列“包含”筛选，激活列标记变蓝，点击外部或按Esc关闭筛选弹窗。
- 配置卡片固定高度完整显示，不使用纵向滚动；窗口默认尺寸`1220,940`，最小`1040,800`。
- 标题与实时刷新开关之间提供【重新获取选择的文件】：读取资源管理器当前选中的文件并替换输入；选择为空时提示“未选中任何文件”。重新获取会取消正在进行的扫描/校验，执行文件操作期间不可用。
- 方案1的【执行】位于【取消】之后；方案2/3的【完成】位于【取消】之后。
- 日期卡片提供“文件名日期与EXIF不一致时用EXIF”开关；默认关闭，开启后仅在生效日期本来采用文件名日期且两者日历日期不同时改用EXIF拍摄日期。
- 预设词典为 `{预设名: 配置JSON字符串}` 扁平结构，配置内`presetVersion`保持0.05；三套方案共用，新开关随预设保存与载入。
- 执行配置、执行后校验、传输性能与RAS策略见 [开发说明](../doc/开发说明.md) 与 [测试报告](../doc/测试报告.md)。

## 6. 重新生成

```bash
python3 tools/build_quicker_code.py
python3 tools/build_release.py
```

`build_release.py` 会：

1. 生成完整开发版 `dist/CustomWindow.xaml` 与 `dist/QuickerAux.cs`（DeliveryMode=0）。
2. 从共享 XAML 移除执行配置块和完成按钮，生成方案1，并把【生成输出】改为【执行】。
3. 从共享 XAML 移除【生成输出】按钮，生成方案2。
4. 方案3在方案2基础上替换窗口标题与提示，生成“重复获取+重命名+执行”版本。
5. 在方案1/2/3 的辅助代码中写入 `DeliveryMode=1/2/3`。

## 7. Quicker 动作组装

| 参数 | 值 |
|---|---|
| 操作类型 | 显示窗口并等待关闭 |
| 窗口XAML代码 | 对应方案1/2/3目录的 `CustomWindow.xaml` |
| 辅助C#代码 | 对应方案1/2/3目录的 `QuickerAux.cs` |
| 窗口标识 | `BatchRenamerWindow` |
| 窗口尺寸 | `1220,940` |
| 自动关闭时间 | `0` |

方案1【执行】、方案2/3【完成】都会关闭窗口，从而继续执行 Quicker 后续步骤；如需放弃输出，使用【取消】。方案2/3执行后窗口保持打开，可反复执行或重新获取选择。

## 8. 预设变量持久化

- Quicker 变量的“保存为状态”只负责跨运行保留变量值，不等于窗口数据映射。
- 必须配置以下映射，窗口才能读取和写回预设：
  - `preset:{批量重命名器预设}`
  - `extensionPresets:{扩展名预设}`
- 窗口启动时 `OnWindowLoaded` 会读取这两个映射；缺失时尝试通过 `GetVarValue` 读取动作变量。
- 【批量重命名器预设】统一为扁平结构：key是预设名称，value是该预设完整配置的JSON字符串。
- 【扩展名预设】同样为扁平结构：key是预设名称，value是扩展名列表字符串，例如 `{"图片":"jpg;png"}`。
- 点击【保存预设】时会通过 `winContext.Context.SetVarValue` 直接写回动作变量，不需要在自定义窗口后追加变量赋值步骤。
- 预设下拉列表每项右侧提供🖊重命名与❌删除；点击按钮不会载入该项。删除前会显示预设名称并提示不可撤销，确认后立即写回变量；删除最后一个预设后下拉列表关闭。
- 载入预设时读取选中key的value，解析JSON并恢复全部配置；旧嵌套结构和旧版单预设会自动迁移。
- 旧嵌套结构识别不依赖 `presetVersion`；映射值为空词典或空字符串时会回退读取动作变量；保存同名且无变化的预设也会回写一次，完成结构迁移。
- “保存为状态”的词典可能以JSON文本读回；窗口启动时会解析JSON文本并还原词典，再载入预设。
- 点击【完成】/【执行】时会把当前预设库回写一次；扩展名预设库非空时也会回写。
- 新增或修改配置后，仍需点击【保存预设】/【保存扩展名预设】才会进入预设库；【完成】不会把未保存的当前配置自动命名为新预设（预设库为空时除外，会写入“默认”）。
- 如果重开动作仍没有预设，请检查：
  1. 动作变量类型是否为“词典”；
  2. 变量名是否与映射完全一致；
  3. 数据映射是否同时包含 `preset` 和 `extensionPresets`；
  4. 是否在保存预设后正常关闭窗口；
  5. 动作变量的状态值是否为JSON文本（窗口应能自动解析；若仍失败，请保留调试报告）。
