## 3. 运行环境与约束

依据 Quicker 官方文档 [1][2]：

- 【自定义窗口】根据 XAML 创建 WPF 窗口，支持简单的数据绑定和事件。
- XAML 必须去掉 `x:Class`，不能指定事件处理方法，需要注册 `xmlns:qk="https://getquicker.net"`。
- 窗口数据保存在词典中；窗口关闭时，【数据映射】中关联的动作变量会被写回。
- 【辅助C#代码】提供 `OnWindowCreated`、`OnWindowLoaded`、`OnButtonClicked` 回调。
- Quicker 自定义窗口的辅助代码按 C# 5.0 语法编译，因此本项目未使用字符串插值、`?.`、`nameof`、表达式体成员等较新语法。
- 项目只使用 .NET Framework 与 WPF 标准库；`System.Windows.Forms` 仅用于 `FolderBrowserDialog` 和 `MessageBox`，与官方文档示例一致。

## 4. 架构设计

### 4.1 总体结构

```text
Quicker 动作变量
  ├─ 输入文件路径（列表）
  ├─ 最早起始年份（整数）
  └─ 批量重命名器预设（词典）
          │
          ▼
【自定义窗口】数据映射 → 窗口 dataContext
          │
          ▼
OnWindowLoaded
  ├─ 读取配置、初始化控件与胶囊编辑器
  ├─ 收集输入路径（判断文件/文件夹、去重、规范化）
  ├─ 启动扫描线程：FileInfo + EXIF
  └─ 启动哈希线程（仅模板含【校验码】时）
          │
          ▼
ObservableCollection<Dictionary<string,object>> → DataGrid 三列预览（动作、源路径、目标路径）
          │
          ├─ 配置变化 → RecomputeAll → 目标路径与动作实时刷新
          ├─ 行悬浮 → Details 文本（全部日期、大小、校验码、动作、执行结果、状态）
          ├─ 生成输出 → 方案1：两个路径列表 + 预设词典
          ├─ 完成 → 写回方案对应输出并关闭窗口
          └─ 执行 → 方案2：按动作并行复制/移动/重命名 → 校验与状态回写
```

### 4.2 模块职责

| 模块 | 职责 | 依赖 |
|---|---|---|
| `RenamerCore.cs` | 文件名日期提取、算法位数、校验码格式、CRC32/BLAKE3/MD5/SHA-256、模板解析、路径规范化与校验、配置与预设转换 | 仅 BCL |
| `CustomWindow.Aux.cs` | 控件查找与事件、配置同步、文件扫描、EXIF 读取、哈希调度、DataGrid 行数据、胶囊编辑器、预设载入/保存、输出 | 核心逻辑、WPF、WinForms 对话框 |
| `CustomWindow.xaml` | 窗口布局、样式、三列表格、执行配置区、状态栏、胶囊按钮 | WPF |

依赖方向为 `XAML/UI → Core`，核心逻辑不引用 WPF，便于在 Linux/Mono 下编译测试。

### 4.3 线程模型

| 线程/机制 | 工作内容 | 与 UI 的交互 |
|---|---|---|
| UI 线程 | 控件事件、配置读取、布局结果应用、DataGrid 刷新、输出 | 直接操作 |
| 扫描调度器 | 4~12 个后台线程按 32 个文件分块领取任务；读取 `FileInfo` 元数据，云端占位跳过 EXIF 内容 | 独立发布线程按输入顺序合并，累计约 200 项后 `Dispatcher.BeginInvoke` 批量加入 UI |
| 布局计算 | 超过 1024 行时后台线程计算目标路径/文件名；`RunIndexedParallel` 按索引原子分发，最多 8 线程 | 完成后一次性投递 `ApplyLayouts`，由 UI 线程应用结果 |
| 目标存在性检查 | 按唯一目标并行 `File.Exists`/`Directory.Exists`，最多 12 线程 | 结果写入各自槽位，随布局一起应用 |
| 哈希线程 | 顺序计算文件校验码 | 按约 120 ms 节流投递进度；完成后触发重算 |
| 执行线程 | 1~8 个后台线程按队列执行复制/移动/重命名与执行后校验 | 每项完成后 `Dispatcher.BeginInvoke` 只更新行数据并置脏标记；`DispatcherTimer` 合并刷新行状态 |
| `DispatcherTimer` | 文本配置 250 ms 防抖；执行状态 200 ms 刷新 | 防抖后统一刷新；执行计时合并行刷新并更新状态文本 |

并发控制：

- 扫描与哈希均使用递增的 generation 编号；窗口关闭、重新扫描或切换算法后，旧线程的结果会被丢弃。
- 扫描调度器用 `Interlocked.Increment` 分配分块，分块结果只写自己的数组槽位；发布线程按槽位顺序合并，保证列表顺序与输入一致。
- 布局计算使用独立的 `_recomputeGeneration`：配置变化、日期刷新、开始扫描、关闭窗口都会递增；后台线程在每个索引前检查代际号，过期结果不写回。
- 布局结果写入独立的 `RowLayout` 槽位，后台线程不修改绑定到 DataGrid 的行词典；只有 UI 线程的 `ApplyLayouts` 才写回行数据。
- 哈希缓存使用 `lock` 保护，键为 `路径|算法`；布局计算与哈希并行时，若缓存已齐但仍有“计算中”行，会补一次同步重算。
- UI 控件、`_files`、`_rows` 只在 UI 线程读写；执行期间禁止重算，避免覆盖执行状态。
- 静态状态按单窗口使用设计；`Window_Closed` 会校验窗口引用，避免旧窗口清理新窗口状态。
- 执行队列按索引原子领取；取消时停止领取新项，在途复制/跨卷移动通过取消回调尽快停止；窗口关闭确认后等待执行线程全部退出再关闭。

### 4.4 状态与生命周期

- `OnWindowCreated`：初始化输出列表为空，避免取消后残留上一次结果。
- `OnWindowLoaded`：重置静态状态、建立默认配置、绑定事件、开始扫描。
- 窗口关闭：递增 generation、停止防抖计时器、清理控件引用与缓存。
- 默认不自动载入预设；用户点击【载入预设】后才应用，符合需求中“载入”按钮的显式交互。
- 实时刷新关闭时，配置变更只更新配置与日期数据并置 `_previewDirty`；`RecomputeAll` 与哈希进度刷新会被该标记阻止，直到【预览】/【生成输出】执行完整刷新。
- 扫描结束、预设载入、开启实时刷新、手动预览会清除 `_previewDirty` 并完整重算。

## 5. 功能实现说明

### 5.1 输入路径与文件筛选

1. 兼容 `List<string>`、`List<object>` 及单个字符串。
2. 使用 `Path.GetFullPath` 规范化；相对路径按 Quicker 进程当前目录解析。
3. 先判断目录：`Directory.Exists` 为真则跳过并计数。
4. 再判断文件：`File.Exists` 为假则跳过并计数。
5. 使用 `HashSet<string>(OrdinalIgnoreCase)` 去重，保持首次出现顺序。
6. 文件夹、无效路径不进入表格；状态栏显示跳过数量。
7. 过滤器（扩展名列表）：
   - 扩展名列表支持逗号、分号、空格、换行、`|` 分隔，支持 `*` 通配全部；空列表表示不过滤。
   - 决策模式 `skip`（排除名单）：命中列表的文件跳过，未命中文件按模板执行。
   - 决策模式 `copy/move/rename`（白名单）：仅命中列表的文件执行对应动作，未命中文件跳过。
   - 动作自动匹配：`rename` 且目标目录与源目录相同 → 重命名；目标目录变化 → 复制；`copy` → 复制；`move` → 移动。
   - 被跳过文件不计算目标路径、不计算哈希、不进入输出列表；表格中以灰色行显示“过滤跳过”。
8. 扩展名预设：
   - 独立词典变量【扩展名预设】；保存命名列表；载入时选择覆盖或追加。
   - 保存后尝试实时写回动作变量。

### 5.2 日期属性

#### 文件名中的日期

- 格式1：`yyyy-mm-dd`，正则 `(?<!\d)(\d{4})-(\d{2})-(\d{2})`。
- 格式2：`yyyymmdd`，正则 `(?<!\d)(\d{8})`。
- 先验条件：匹配位置为字符串起始或前一个字符不是数字；不校验后边界，日期后允许是时间、文件名或连接符。
- 年份范围：`最早起始年份` 至当前年份，含边界；月份 1–12，日期按公历校验。
- 优先尝试格式1；格式1没有有效日期时再尝试格式2；同一格式内取第一个有效日期。
- 只匹配文件名（不含扩展名）。

#### EXIF 拍摄日期

- 通过 WPF `BitmapDecoder` + `BitmapMetadata` 读取，避免额外依赖。
- 查询顺序：`DateTimeOriginal (36867)` → `DateTimeDigitized (36868)` → `DateTime (306)`。
- 仅对常见图片扩展名尝试：`.jpg/.jpeg/.tif/.tiff/.png/.bmp/.gif/.heic/.heif/.webp`；实际能否读取取决于系统 WIC 编解码器。
- 支持 `yyyy:MM:dd HH:mm:ss`、`yyyy-MM-dd HH:mm:ss` 等格式，并做宽松解析回退。

#### 生效日期

- 修改日期、创建日期来自 `FileInfo.LastWriteTime` / `CreationTime`。
- 【配置3.1】选中的日期来源优先。
- 递补1~5在同一行；每项可选四类日期来源、空值、自定义、跳过；递补5默认空值。
- 递补按顺序处理：日期来源可用则采用；空值=三个日期胶囊为空并停止；自定义=使用统一自定义值并停止；跳过=该文件不处理、不输出。
- 空值/空字符串下【日期yyyy】【日期mm】【日期dd】都为空。
- 日期卡片新增“文件名日期与EXIF不一致时用EXIF”开关，默认关闭；开启后若文件名日期与EXIF日历日期不同，且生效日期本来会采用文件名日期（主选或递补），则改用EXIF拍摄日期，来源显示为EXIF。
- 仅比较日历日期（yyyy-MM-dd），时间部分不同不算冲突；主选为修改/创建/EXIF时该开关不覆盖主选。
- 行悬浮信息中显示“生效日期（来源：…）”；日期缺失时显示替换值/跳过状态。

### 5.3 校验码

| 算法 | 最高16进制位数 | 实现 |
|---|---:|---|
| CRC32 | 8 | 多项式 `0xEDB88320`，流式计算 |
| BLAKE3 | 64 | 托管流式实现，默认32字节输出 |
| MD5 | 32 | `System.Security.Cryptography.MD5` |
| SHA-256 | 64 | `System.Security.Cryptography.SHA256` |

格式规则：

```text
前缀 + 算法标识 + "-" + 截断后的16进制校验码 + 后缀

默认前缀 "["、后缀 "]"：
位数等于算法最高位数： [CRC32-7f7f7f7f]
位数小于最高位数：     [CRC32_4-7f7f]
自定义前缀/后缀：      CHK:CRC32_4-7f7f:END
```

- 位数范围 1 至算法最高位数；切换算法时，如果原位数等于旧算法最高位数，则自动改为新算法最高位数，否则按新算法上限截断。
- 截取规则：取完整16进制串的前 N 位（高位）。
- 前缀、后缀默认分别为 `[` 和 `]`，直接位于“算法标识-校验码”两侧，不再额外套固定方括号。
- 模板不含【校验码】时不计算哈希；含有时在后台顺序计算，完成后刷新预览。
- 哈希失败（权限、占用、算法不可用等）会将行标记为错误。

### 5.4 模板与胶囊编辑器

支持的七个胶囊：

| 胶囊 | 值 |
|---|---|
| 【日期yyyy】 | 生效日期的四位年份 |
| 【日期mm】 | 两位月份 |
| 【日期dd】 | 两位日期 |
| 【根路径】 | 当前文件所在目录或用户选择的固定目录 |
| 【源文件名】 | 不含扩展名的文件名 |
| 【扩展名】 | 不含点的扩展名 |
| 【校验码】 | 按 5.3 生成的校验码文本 |

编辑器实现：

- 使用 `RichTextBox`；胶囊渲染为 `InlineUIContainer` + `Border` 的可视元素。
- 点击胶囊按钮时，将胶囊插入到最近一次记录的光标位置；插入后光标移动到胶囊之后。
- 文本与胶囊统一序列化为带 `【…】` 的模板字符串，用于预览与预设保存。
- 载入预设或恢复默认模板时，重新解析模板并生成胶囊。
- 未知 `【…】` 胶囊会被保留显示，但目标路径计算会报“模板包含未知胶囊”。
- 默认模板为 `【根路径】/【日期yyyy】.【日期mm】/aaa/bbb/【源文件名】-【校验码】.【扩展名】`。

### 5.5 目标路径组合与校验

- 根路径模式：
  - `current`：每个源文件所在目录（默认）。
  - `custom`：用户通过文件夹选择器指定的固定目录。
- 模板未包含【根路径】且渲染结果不是绝对路径时，自动拼接到根路径下。
- 允许模板直接写绝对路径（如 `D:/Out/...`），此时忽略根路径。
- 路径分隔符统一为 Windows 反斜杠；连续分隔符折叠；保留 UNC 的 `\\server\share` 前缀。
- 不解析 `..`：含 `.` 或 `..` 段的路径判为错误。
- 校验项（跨平台并集）：
  - 必须是 `X:\...` 或 `\\server\share\...` 绝对路径。
  - 非法字符并集：`< > : " / \ | ? *`、ASCII 控制字符（NUL 等）；`/` 在规范化阶段转为分隔符。
  - 路径段不能为空、不能是 `.`/`..`、不能以空格或点结尾。
  - Windows 保留设备名（CON/PRN/AUX/NUL/CLOCK$/CONIN$/CONOUT$/COM0–9/LPT0–9）判为错误。
  - 路径段长度不超过 255 字符且 UTF-8 不超过 255 字节。
  - 总路径不超过 259 字符且 UTF-8 不超过 1024 字节（取 Windows/macOS 的严格限制）。
  - 必须包含文件名。
- 冲突处理：
  - 批内目标路径重复（忽略大小写）→ 标记“目标重复”。
  - 目标文件或目录已存在且不等于源路径 → 标记“目标已存在”。
  - 目标等于源路径 → 标记“无变化”，仍视为可输出。
- 错误提示：
  - 顶部 ErrorBanner 汇总异常数量与前 5 类错误，红字显示。
  - 表格异常行使用红底高亮；行悬浮显示完整错误。
- 不检查 POSIX 文件名规范化差异与 Windows 长路径前缀 `\\?\`，见第 9 章。

### 5.6 预设

预设使用 Quicker 词典；单套配置为扁平键值，多套命名预设使用扁平词典存储。单套配置键名与类型如下：

| 键 | 值示例 | 说明 |
|---|---|---|
| `presetVersion` | `0.05` | 单套配置结构版本 |
| `rootMode` | `current` / `custom` | 根路径模式 |
| `rootPath` | `D:\Output` | 固定根路径，模式为 current 时也会保留 |
| `startYear` | `2000` | 最早起始年份（字符串存储） |
| `filterExtensions` | `jpg;png` | 过滤器扩展名列表 |
| `filterMode` | `skip` / `copy` / `move` / `rename` | 跳过（排除名单）或复制/移动/重命名（白名单） |

| `dateFallbackOrder` | `filename,exif,modified,created,empty` | 递补1~5（日期来源/空值/自定义/跳过） |

多预设词典结构（扁平）：

```text
{
  "预设名A": "{\"rootMode\":\"current\",...}",
  "预设名B": "{...}"
}
```

- `BuildPresetDictionary` 先规范化配置，再输出单套配置的全部键。
- 词典统一为扁平结构：`{ "预设名": "配置JSON字符串" }`；窗口内通过【载入预设】下拉选择、【保存预设】命名保存。
- 预设下拉列表每项右侧提供🖊重命名与❌删除按钮；按钮使用 `Uid` 区分动作、`Tag` 绑定预设名，通过 ListBox 的路由 Click 统一分发。
- 重命名复用名称输入对话框（标题“重命名预设”、确认按钮“重命名”），预填原名称；校验空名、重名（不区分大小写），允许仅变更大小写，名称未变化时不修改。
- 删除先弹出“不可撤销”确认框；确认后从词典移除并立即 `SavePresetStore` 写回动作变量。
- 重命名/删除后调用 `RefreshPresetPopupAfterEdit` 刷新列表并重新打开下拉框；列表为空时关闭下拉框。
- 点击🖊/❌通过 `PresetListBox_PreviewMouseDown` 设置抑制标记，避免触发 ListBox 选择与预设载入。
- `BuildFlatPresetDictionary` 把每套配置序列化为JSON字符串；`ParsePresetDictionary` 在载入时解析选中value为配置词典。
- 兼容旧嵌套结构 `{ presetVersion, presets: { 名称: 配置 } }` 和更旧单预设词典；读取时自动迁移，保存时统一写扁平结构。
- 旧嵌套识别不依赖 `presetVersion`：只要 `presets` 的值不是单套配置就按旧结构处理；`LooksLikePresetConfigDictionary` 要求至少命中2个配置键，避免把名为 `template`、`presets` 的扁平预设误判为单套配置。
- 全部配置键由 `PresetConfigKeys` 统一定义，`BuildPresetDictionary` 与 `CreateDefaultConfig` 键集合一致。
- 同名判断忽略大小写；覆盖前显示变更项目（旧值→新值）；配置无变化时也回写一次扁平结构，顺带完成旧结构迁移。
- 点击【生成输出】时若预设词典为空，会自动把当前配置保存为“默认”预设输出。
- 保存预设时通过反射调用 `winContext.Context.SetVarValue` 直接更新动作变量【批量重命名器预设】，不需要在自定义窗口后追加变量赋值步骤；窗口关闭时数据映射继续兜底。
- 反射查找 `GetVarValue/SetVarValue` 时同时检查运行时类型与实现接口；Quicker 上下文可能以显式接口实现提供这两个方法。
- `OnWindowLoaded` 显式调用 `PrimePresetVariables`：优先使用数据映射的 `preset/extensionPresets`；映射值为空词典或空字符串时同样回退 `GetVarValue` 读取【批量重命名器预设】/【扩展名预设】。
- `PrimePresetVariables` 调用 `NormalizePresetVariable`：若变量值是 JSON 文本，先用核心 `TryParseJson` 解析并还原为词典，再进入预设载入流程。
- `LoadPresetStore` 调用核心 `ParsePresetDictionary`：选中预设的value是JSON字符串时，解析后交给 `ApplyPresetDictionary` 恢复全部配置。
- 【完成】/【执行】调用 `EnsureDefaultPreset`，回写当前预设库；扩展名预设库非空时一并回写。
- 仅设置 Quicker 变量“保存为状态”不等于数据映射，必须配置 `preset:{批量重命名器预设}` 与 `extensionPresets:{扩展名预设}`。
- 调试报告证据：`批量重命名器预设` 的启动值为 `string(len=529)`（JSON 文本），`扩展名预设` 为 `Dictionary(count=2)`；说明嵌套词典的状态回读会退化为文本，扁平字符串词典更稳定。
- 旧版加载失败的典型原因：状态里是嵌套词典JSON文本，窗口只按嵌套结构读取；改为扁平结构后每个value都是字符串，解析路径更直接。
- 扩展名预设独立存于【扩展名预设】词典，同样使用扁平结构：`{ "名称": "jpg;png" }`。
  - `BuildFlatExtensionPresetDictionary` 构建扁平词典；`ParseExtensionPresetDictionary` 解析扁平结构与旧嵌套结构。
  - 载入时询问覆盖或追加；追加使用扩展名规范化后合并。
  - 保存后同样尝试实时写回动作变量，并在窗口关闭时由数据映射兜底。
- 预设只通过动作词典输入/输出，不写本地文件。

### 5.7 输出契约

方案1的【执行】（原【生成输出】）点击后：

1. 立即读取当前 UI 配置并刷新预览（等价于手动预览），避免输出旧配置。
2. 若仍有校验码在计算，提示等待。
3. 若存在异常行但仍有就绪行，弹窗确认后仅输出就绪行。
4. 使用成对列表构造三个输出列表：
   - `origPaths`：列表【原路径和文件名】。
   - `targetPaths`：列表【目标路径和文件名】。
   - `actions`：列表【执行动作】。
   - `preset`：词典【批量重命名器预设】，包含已保存的多套命名预设；若尚未保存任何预设，则自动写入当前配置为“默认”。
5. 三个列表第 n 项来自同一源文件，顺序与输入文件顺序一致（去重后），不包含文件夹、无效路径、异常行、计算中行、跳过项。
6. 方案1没有【完成】按钮；点击【执行】后写三个列表并关闭窗口。方案2不生成、不写入 `origPaths`/`targetPaths`/`actions`；【完成】只写预设并关闭。

预览、配置变化与生成输出阶段不执行任何文件写入操作；只有方案2的【执行】会修改文件。

### 5.8 实时刷新与手动预览

- 【实时刷新】默认开启。
- 开启时：配置变更立即重算目标路径；【预览】按钮禁用。
- 关闭时：
  - 配置变更只更新配置与必要的日期数据，目标路径保持上一次预览结果。
  - 状态栏提示“配置已变更，点击【预览】刷新目标路径”，【生成输出】禁用。
  - 点击【预览】时，读取当前配置并完整刷新预览；刷新完成后恢复【生成输出】。
- 实时刷新关闭时，日期相关配置变更仍会重新计算文件名日期/生效日期并刷新行悬浮信息，但目标路径列保持旧值，直到手动预览。
- 开启实时刷新会立即完整刷新一次，以吸收关闭期间累积的配置变更。

### 5.10 执行实现

- 执行队列：从展示列表取非跳过、非异常、非计算中、目标非空的行；执行前写出三个输出列表。
- 并行：`execParallel` 限制在1~8；创建同等数量的后台线程，按 `Interlocked.Increment` 领取队列索引。
- 单文件执行：
  - 检查源文件存在、目标目录有效；目标目录不存在时 `Directory.CreateDirectory`。
  - 复制：调用核心传输引擎 `CopyFileWithRetry`，临时文件+原子改名，不覆盖。
  - 移动：同卷 `MoveFileWithRetry`；跨卷先复制、校验、删除源文件，删除失败时回滚目标。
  - 重命名：同目录 `MoveFileWithRetry`；目标与源相同视为无需操作。
  - 目标已存在：该项报错，不覆盖。
- 执行后校验（复制/移动且开关开启）：
  - 读取源校验码；模板含【校验码】时优先使用预览阶段缓存。
  - 计算目标文件校验码并比较。
  - 若模板含【校验码】，生成目标文件名应包含的校验码标记并核对。
- 状态：
  - `ExecState=done` 行绿底；`ExecState=error` 且 `HasError=true` 行红底；悬浮 `Details` 包含执行结果与错误。
  - 状态文本显示执行总数、成功数、错误数、传输速度（字节/秒）、执行速度（项/秒）。
- 并发安全：UI 行更新通过 `Dispatcher.BeginInvoke`；每项更新后刷新 DataGrid；计数使用 `Interlocked`。
- 取消与关闭：执行中关闭窗口会确认；确认后设置停止标记，等待所有执行线程退出后再关闭，避免窗口关闭后继续改文件。

### 5.11 文件传输性能与RAS

传输引擎位于 `RenamerCore.cs`，与界面解耦，可在 Linux/Mono 下用真实文件测试。

| 能力 | 实现 |
|---|---|
| 原生复制 | Windows 下优先 `CopyFileEx`（进度回调、失败即存在、保留属性/时间戳） |
| 托管回退 | 原生不可用/不支持时使用 `FileStream` 流式复制 |
| 缓冲策略 | 网络/UNC 256 KiB；光驱 64 KiB；可移动盘 1 MiB（≥512 MiB 用2 MiB）；固定盘/未知盘 1 MiB（≥1 GiB 用4 MiB） |
| 预分配 | 固定盘且文件≥64 MiB 时 `SetLength` |
| 临时文件 | 目标目录下 `.qk-随机.tmp`，成功后改名；失败/取消清理 |
| 同卷移动 | `File.Move` + 3次瞬态重试 |
| 跨卷移动 | 复制→校验→删除源；删除失败回滚目标；校验失败保留源 |
| 空间检查 | 固定盘/可移动盘检查可用空间并预留32 MiB或1%；网络路径跳过 |
| 稳定性 | 复制前后比较源文件长度与最后写入时间 |
| 重试 | 共享冲突/锁定/网络超时/设备未就绪等最多3次，200/400/800 ms |
| 进度 | 原生回调或托管读循环按增量上报，执行状态实时更新传输速度 |
| 元数据 | 托管复制后保留创建时间、修改时间、文件属性 |
| 失败清理 | 临时文件、未通过校验的复制目标、跨卷移动失败目标均尽量删除 |

SSD/HDD无法通过标准 `DriveInfo` 可靠区分，当前统一按固定盘策略；如需按介质类型细分，需引入WMI/设备查询（见需求Q-14）。

### 5.13 交互窗口与执行性能优化

#### 交互窗口

| 优化 | 实现位置 | 说明 |
|---|---|---|
| EXIF 元数据模式 | `TryReadExifDate` | `BitmapCacheOption.OnLoad` 改为 `None`；只读 WIC 元数据，不解码像素，扫描照片时内存与 CPU 明显下降 |
| 模板校验码检测缓存 | `TemplateNeedsHash` | `【校验码】` 正则结果按模板字符串缓存；`BuildDetails`/`UpdateStatus` 不再逐行执行正则 |
| 状态计数单遍 | `CountRows` 四输出重载 | 一次遍历同时统计就绪/异常/计算中/跳过，移除第二次全表扫描 |
| 日期刷新去词典分配 | `ResolveDateValue` 四值重载 | 批量刷新日期时不再为每一行创建 `Dictionary<string, DateTime?>` |
| 哈希进度节流 | `HashWorker` | 由“每 5 个文件”改为“最早约 120 ms 一次”，完成时强制上报，降低 Dispatcher 排队 |
| 哈希缺失检查合并加锁 | `EnsureHashWorker` | 一次 `lock` 内完成全表缓存查询，避免逐文件加锁 |
| 表格虚拟化 | `CustomWindow.xaml` | 保持 `EnableRowVirtualization`/`EnableColumnVirtualization` 与容器回收 |

#### 执行

| 优化 | 实现位置 | 说明 |
|---|---|---|
| 行状态合并刷新 | `ReportExecutionRow` / `FlushExecutionUi` / `ExecutionTimer_Tick` | 工作线程完成一项只更新行字典并置 `_execUiDirty`；200 ms 定时器统一 `Items.Refresh` 一次，避免每个文件一次全表刷新（原为 O(N²) 事件量） |
| 同卷移动免内容哈希 | `ExecuteOneFile` / `VerifyMovedFileName` | 同卷移动只改目录项；开启校验时仅核对目标文件名中的校验码，不再读取源/目标内容各算一次哈希 |
| 跨卷/复制保持内容校验 | `VerifyExecutedFile` | 仍比较源/目标内容哈希；校验失败回滚逻辑不变 |
| 执行配置快照 | `Execute_Click` | 算法、位数、前后缀、校验开关、模板是否含【校验码】在执行开始时缓存，逐文件不再读词典/正则 |
| 目标目录缓存 | `EnsureExecutionDirectory` | 执行会话内每个唯一目录只检查/创建一次，减少重复 `Directory.Exists` |
| BLAKE3 去块分配 | `Blake3Compress` / `Blake3ChunkOutput` / `Blake3ParentCv` | 使用 `[ThreadStatic]` 临时缓冲区，消除每 64 字节块的 `state/message/permuted/output` 分配；仍保持流式分块，不整文件入内存 |

未采用的方案：

- 目标路径存在性检查异步化：0.0.17 起已随布局在后台/并行执行（最多12线程），但执行前仍要求布局已完成，避免“检查未完成即可执行”的竞态；小数据量保持主线程内联。
- 自定义批量通知集合：需要新增类型并改动绑定生命周期，收益低于上述合并刷新；暂不引入。
- 复制缓冲/原生 `CopyFileEx` 策略：已在 0.05 系列完成，本次不改动。

### 5.14 性能显示与瓶颈判断

底部 `PerfText` 固定显示两行：

- `属性读取：速度（样本/耗时，工作线程+发布线程，平均ms/个，瓶颈，CPU占用）`
- `目标路径：速度（样本/耗时，计算线程+存在性线程，瓶颈，CPU占用）`

实现：

| 项目 | 做法 |
|---|---|
| 速度 | `DateTime.UtcNow.Ticks` 记录阶段起止，`个数 / 墙钟秒`；扫描还累计每个文件的 `BuildFileItem` 耗时求平均 |
| 线程数 | 扫描记录实际工作线程数与发布线程数；目标路径由 `RunIndexedParallel` 返回实际创建线程数（0 表示主线程内联），并记录存在性检查线程数 |
| 瓶颈 | `ClassifyPerformanceBottleneck` 统一判定：样本<64或耗时<50ms为“样本小”；CPU占用≥65%为CPU，≤30%为I/O，其间为混合 |
| CPU占用 | `Process.TotalProcessorTime` 差值 /（墙钟×可用计算核心数）；可用核心数取 `min(逻辑核心, 计算线程)`，避免多核机器误判 |
| 状态 | 扫描开始显示“进行中”；实时预览关闭时目标路径显示“待刷新”；异步布局完成后再替换为最终数据 |

### 5.15 目标冲突处理

布局完成后按以下顺序处理目标已存在：

| 步骤 | 实现 | 说明 |
|---|---|---|
| 目标类型 | 存在性检查并行区分文件/目录 | 目录不读取内容，直接进入加序号 |
| 内容比较 | `TryCompareFileContent` | 大小 → CRC32（`ConflictCompareAlgorithm`）→ 逐字节；云端占位直接判为无法比较 |
| 相同 + 复制 | 动作改为“跳过”，`IsSkipped=true` | 不执行、不输出；预览保留目标路径 |
| 相同 + 移动/重命名 | 动作改为“删除原文件” | 执行线程删除前再次比较，目标变化则取消 |
| 不同/无法比较 | `BuildNumberedSuffixPath` + `TryBuildAvailableTarget` | 追加 ` (n)`，从1到9999，跳过磁盘已存在与批内已占用 |
| 批内重复 | 顺序解析，后出现者加序号 | 状态显示“批内目标重复，已加序号” |

执行层 `ExecuteOneFile` 新增“删除原文件”分支：重新比较源/目标，确认相同后 `File.Delete(source)`；目标为云端占位或内容变化时拒绝删除。

### 5.16 预览列表筛选与排序

| 功能 | 实现 | 说明 |
|---|---|---|
| 文本筛选 | `GridFilterText` + `GridRowFilter` | 匹配源路径、目标路径、文件名、异常、执行结果；200ms 防抖 |
| 状态筛选 | `GridStatusFilterCombo` | 全部/就绪/异常/跳过/校验中/执行成功/执行失败 |
| 计数 | `GridFilterCountText` | 显示 `显示 X / Y 行` 或 `共 Y 行` |
| 排序 | `PreviewGrid_Sorting` + `SortPreviewRows` | 点击表头升/降序；按 `_rows` 重建集合，字典行使用自定义比较器 |
| 表头逐列筛选 | `HeaderFilterPopup` + `_columnFilters` | 五个表头的▼标记打开共享弹窗；逐列包含匹配，可与文本/状态筛选叠加；激活列标记显示蓝色 |
| 状态合并显示 | `BuildStatusDisplay` + `StatusDisplay` | 异常信息并入状态列：“状态：异常”；异常为空时只显示状态；执行完成后同步刷新 |
| 列宽 | XAML | 动作78、状态104、执行结果160固定；源路径2*、目标路径3*，窗口变宽只扩展路径列 |
| 新增列 | XAML | 状态（合并异常）、执行结果；各列设置 `SortMemberPath` |
| 与执行的关系 | 仅替换 `_grid.ItemsSource` | `_files` 顺序不变，执行与输出顺序不受影响 |

### 6.3 交互流程

1. 打开窗口 → 自动读取输入路径与属性，表格逐步填充；先按过滤器扩展名与决策模式标记跳过行。
2. 选择根路径模式；选择“其他文件夹”立即弹出文件夹选择器，取消且无历史路径时回退到“当前文件夹”。
3. 修改起始年份 → 重新计算文件名日期；修改日期来源/递补1~5/EXIF冲突开关 → 重新选择生效日期；递补选择空值/自定义/跳过时立即按对应语义处理。
4. 编辑模板或点击右侧胶囊 → 250 ms 防抖；实时刷新开启时立即刷新目标路径，关闭时提示手动预览。
5. 修改校验算法/位数/前后缀 → 更新格式预览；实时刷新开启时按需后台重算哈希。
6. 实时刷新关闭时，配置变更后点击【预览】刷新；【生成输出】在预览过期时禁用。
7. 发现非法路径 → 顶部红字提示，异常行红底高亮；悬浮行可查看完整错误；跳过行不进入错误统计。
8. 点击【载入预设】→ 顶部下方弹出预设列表，单击名称载入；旧版单预设显示为“默认”。
9. 点击【保存预设】→ 输入名称；同名时显示变更项目并确认覆盖；保存后写入多预设词典并尝试实时写回动作变量。
10. 点击【载入扩展名预设】→ 下拉选择名称，询问“覆盖/追加/取消”；点击【保存扩展名预设】→ 命名保存并尝试实时写回【扩展名预设】。
11. 方案1点击【执行】输出三个等长、序号配对的列表（原路径、目标路径、动作，排除跳过行）并关闭窗口。
12. 方案2点击【执行】→ 按动作列并行执行；执行中配置区禁用，状态区显示进度、速度与错误数；成功行绿底、失败行红底。
13. 方案2执行中点击取消/关闭 → 确认后停止领取新项，等待已开始项目完成后关闭。
14. 方案2点击【完成】→ 关闭窗口，Quicker 继续执行后续动作步骤。
15. 悬浮任意配置项、卡片标题、胶囊或主要按钮可查看用途、结果与后果。

胶囊编辑器说明：

- 胶囊是原子内联元素；可整体选中后删除。
- 从外部粘贴富文本时，`Span` 内文字会被序列化保留，但不会自动转换为胶囊。
- 光标离开编辑器后仍保留最近光标位置，用于胶囊按钮插入。

## 8. 设计决策与需求映射

需求文档第10章仍有待确认项。当前实现采用以下口径，均可在后续版本调整：

| 需求项 | 当前实现 |
|---|---|
| 文件名日期边界与优先级 | 只校验前边界；格式1优先；同格式取第一个有效日期 |
| 日期来源缺失 | 递补1~5同行；每项可选四类日期、空值、自定义、跳过；默认顺序 filename→exif→modified→created→empty；空值=三胶囊为空并停止，自定义=统一替换并停止，跳过=不处理/不输出 |
| 文件名/EXIF冲突 | 开关默认关闭；开启后仅在生效日期本来采用文件名日期且两者日历日期不同时改用EXIF；时间不同不算冲突 |
| 过滤器 | 扩展名列表 + 决策模式（跳过/复制/移动/重命名）；跳过=排除名单，其余=白名单；空列表不过滤 |
| 动作匹配 | 重命名且目标目录不变→重命名；目标目录变化→复制；复制→复制；移动→移动；跳过→跳过 |
| 执行 | 1~8线程并行；目标目录自动创建；不覆盖已存在目标；跨卷移动先复制校验后删除 |
| 传输引擎 | Windows原生 `CopyFileEx`，托管流回退；按驱动器类型/文件大小选择64 KiB~4 MiB缓冲 |
| 传输RAS | 临时文件+原子改名；3次瞬态重试；空间/稳定性检查；失败清理；时间戳/属性保留 |
| 执行后校验 | 复制/跨卷移动重算目标校验码并与源校验码比较；同卷移动仅核对目标文件名标记；模板含【校验码】时核对文件名 |
| 界面性能 | EXIF只读元数据；模板校验码检测缓存；计数单遍；日期刷新去词典分配；哈希进度120 ms节流 |
| 执行性能 | 行状态200 ms合并刷新；同卷移动免内容哈希；执行配置快照；目标目录缓存；BLAKE3块处理复用缓冲区 |
| 输出 | 方案1：三个列表（原路径、目标路径、动作）；方案2：不输出列表 |
| 交付 | `release/` 两套方案共享源码；方案1仅重命名不执行，方案2执行不输出列表 |
| 完成按钮 | 仅方案2有；关闭窗口并继续 Quicker 后续步骤，只写预设。方案1无完成按钮，点击【执行】写三个列表并关闭 |
| 校验码前缀/后缀 | 直接包裹“算法[_位数]-校验码”，默认 `[`、`]` |
| 预设存储 | 多套命名预设存于 `presets` 嵌套词典；旧版扁平预设识别为“默认”；同名忽略大小写，覆盖前显示变更 |
| 递补兜底 | 递补5默认为空值；空值下三个日期胶囊都为空；也可设为自定义或跳过 |
| 模板未包含【根路径】 | 视为相对路径，拼接到根路径下 |
| 非法/重名/已存在 | 标记错误；异常行不输出；有异常时弹窗确认；顶部红字汇总 |
| 输出顺序与配对 | 输入顺序（去重后），不占位；成对构造，长度与序号严格一致 |
| 默认模板 | `【根路径】/【日期yyyy】.【日期mm】/aaa/bbb/【源文件名】-【校验码】.【扩展名】` |
| 校验码计算时机 | 模板含【校验码】时后台计算；生成输出前等待完成 |
| 实时刷新 | 默认开启；关闭时手动预览，预览过期时禁用生成输出 |
| “当前文件夹” | 每个源文件所在目录 |
| BLAKE3 输出 | 32字节 / 64位16进制，取前 N 位 |
| 路径分隔符 | 统一反斜杠；折叠重复分隔符；保留 UNC 前缀 |
| 跨平台校验 | 非法字符并集 + 保留名 + 段/总路径长度限制 |

## 9. 限制与已知风险

1. **单窗口静态状态**：界面状态保存在静态字段中，按同一时间只打开一个批量重命名器窗口设计；避免同时打开多个实例。
2. **执行会修改文件**：只有点击【执行】才会复制/移动/重命名；预览、生成输出、载入预设均不修改文件系统。执行不覆盖已存在目标。
3. **C# 5.0**：代码按 Quicker 自定义窗口的 C# 5 环境编写；不要直接引入需要更高语言版本的语法。
4. **EXIF 依赖 WIC**：只对常见图片扩展名尝试；RAW 文件、缺少系统编解码器的 HEIC/HEIF/WebP 可能读不到拍摄日期。
5. **无扩展名文件**：默认模板含 `.【扩展名】`，扩展名为空时会形成结尾点并判为非法路径；可自定义模板去掉该点。
6. **跨平台路径长度**：为兼容 Windows/macOS/Linux/Android，当前限制为路径段≤255字符且≤255 UTF-8字节、总路径≤259字符且≤1024 UTF-8字节；会拒绝部分系统本身可接受的长路径。
7. **哈希耗时**：哈希顺序执行，BLAKE3 为托管实现；大批量/大文件时总耗时较长，但 UI 保持响应。
8. **预设不持久化到文件**：依赖 Quicker 动作词典；支持多套命名预设与独立【扩展名预设】。嵌套词典“保存为状态”后可能以 JSON 文本读回，已通过 `TryParseJson` 还原，仍需在 Windows/Quicker 中验证真实状态文件。
9. **实时变量写入依赖接口**：优先反射调用 `winContext.Context.SetVarValue` 直接写回，并同时检查运行时类型与实现接口；若当前 Quicker 版本不暴露上述接口，则退回到窗口关闭时由数据映射写回，此时运行中读取动作变量可能仍是旧值。
10. **过滤器范围**：APP_FileSettle 仓库在本环境不可访问；当前仅实现扩展名列表与跳过/复制/移动/重命名决策，尚未实现关键词、正则、大小、日期等筛选规则。
11. **文件在窗口打开期间变化**：属性只在打开时读取，之后不会自动刷新；需要重新打开窗口。
12. **ToolTip 长路径**：超长源路径可能使悬浮提示较宽；可后续改为带换行的自定义 ToolTip。
13. **实时刷新关闭时**：目标路径列会保持旧值，状态栏与禁用生成输出提示预览过期；日期属性仍会按配置更新。
14. **缺失日期与默认模板**：递补选择空值或自定义空字符串时，默认模板可能形成 `.` 目录段并因此报非法路径；可改为自定义非空日期文本、选择跳过或调整模板。
15. **执行不可完全回滚**：执行中没有全局事务；复制/移动失败会逐项报错并继续其他项目。跨卷移动在删除源文件失败时会尽量删除已复制目标，其余情况保留现状。
16. **并行与磁盘**：高并行复制/移动可能造成磁盘竞争；默认2线程，可按磁盘性能调整。
17. **执行后校验成本**：开启校验会对目标文件再读一遍；大文件或BLAKE3算法会明显增加总耗时。
18. **SSD/HDD无法自动区分**：标准 `DriveInfo` 不提供介质类型；当前统一按固定盘策略，大文件4 MiB缓冲。需要更精细调优时引入WMI/设备查询（Q-14）。
19. **网络/UNC环境差异**：网络路径可用空间可能无法读取，空间检查会跳过；网络吞吐/超时受SMB、VPN、路由器影响，需实机测试。
20. **可移动盘落盘刷新**：为RAS对可移动盘执行 `Flush(true)`，会牺牲部分写入速度换取掉盘安全性。
21. **原生复制回退**：极少数虚拟文件系统不支持 `CopyFileEx` 时回退托管流；两条路径的进度粒度可能不同。
22. **进程崩溃残留**：复制中进程崩溃可能留下 `.qk-随机.tmp`；目标文件不会出现半成品，但临时文件需人工清理，后续可增加启动时按目录清理。
23. **网络/远程权限**：网络共享需要当前进程有读写/删除权限；凭据由Windows管理，本工具不保存网络凭据。
24. **临时文件空间**：复制期间源与目标会同时占用空间；空间检查按单文件大小+预留计算，批量复制时多文件并发可能叠加占用。
