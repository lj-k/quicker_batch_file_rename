## 2. 项目概述

开发一个运行于 Quicker 的批量重命名器，使用 Quicker 的【自定义窗口】动作承载界面。动作需要读取输入文件路径，获取文件属性（重点为多种日期属性），按照用户配置的规则组合出新的目标路径和文件名，并在窗口中实时预览。

该窗口用于配置、预览与执行：预览不修改文件；点击【执行】后按展示列表的动作完成复制、移动或重命名。窗口最终输出两个路径列表、一个动作列表和一个预设词典，供后续动作步骤使用。

## 3. 输入与输出

### 3.1 输入

| 输入项 | 类型 | 说明 |
|---|---|---|
| 【输入文件路径】 | 列表 | 待处理的文件路径集合。处理时先判断是否为文件，文件夹跳过 |
| 【最早起始年份】 | 配置参数 | 默认 2000 年，用于限定【文件名中的日期】可接受的年份范围 |
| 【批量重命名器预设】 | 词典 | 用于载入/保存多套命名配置 |
| 【扩展名预设】 | 词典 | 用于保存和载入过滤器扩展名列表；载入可选覆盖或追加 |

### 3.2 输出

| 输出项 | 类型 | 方案1：仅重命名不执行 | 方案2：执行不输出列表 |
|---|---|---|---|
| 【原路径和文件名】 | 列表 | 输出，仅非跳过且目标有效项 | 不生成、不输出 |
| 【目标路径和文件名】 | 列表 | 输出，仅非跳过且目标有效项 | 不生成、不输出 |
| 【执行动作】 | 列表 | 输出，与两列逐项配对（复制/移动/重命名） | 不生成、不输出 |
| 【批量重命名器预设】 | 词典 | 输入/输出 | 输入/输出 |
| 【扩展名预设】 | 词典 | 输入/输出 | 输入/输出 |

输出约束：

- 方案1输出三个列表（原路径、目标路径、动作），必须序号一致、长度相等，第 n 项来自同一源文件，动作与该源文件的目标路径对应。
- 三个列表只包含非跳过项；过滤跳过、日期跳过、动作跳过均不输出。
- 方案2不初始化、不写入任何路径列表或动作列表变量。
- 展示界面用于预览与执行：预览、配置变化阶段不得修改文件系统；只有方案2点击【执行】后才按列表动作修改文件。
- 方案1没有【完成】按钮；原【生成输出】按钮显示为【执行】，点击后关闭窗口并继续 Quicker 后续动作；方案2保留【完成】按钮。

## 4. 平台与技术约束

依据 Quicker 官方文档，【自定义窗口】具有以下约束 [1][2]：

- 窗口通过 XAML（WPF）定义，支持简单的数据绑定与事件处理。
- XAML 中需要去掉 `x:Class` 属性，不支持在 XAML 中直接指定事件处理方法。
- 需要注册命名空间 `xmlns:qk="https://getquicker.net"`。
- 通过【数据映射】把动作变量引入窗口数据；窗口结束时，窗口数据会写回关联的动作变量。
- 可通过【辅助C#代码】提供 `OnWindowCreated`、`OnWindowLoaded`、`OnButtonClicked` 等回调，用于初始化、事件处理和数据计算。
- 该功能在官方文档中标注为预览状态，可能存在缺陷或发生改动，开发和测试时需考虑版本兼容性。

## 5. 功能需求

### 5.1 文件筛选

1. 遍历【输入文件路径】列表中的每一项。
2. 先判断该项是否为文件。
3. 文件夹直接跳过，不进入预览表格，也不进入最终输出列表。

### 5.2 文件日期属性获取

需要获取并可选择以下四类日期，原文给出的顺序为：

| 顺序 | 日期类型 | 获取规则 |
|---|---|---|
| 1 | 【文件名中的日期】 | 在文件名中匹配日期；按顺序获取任意一个即停止 |
| 2 | 【exif拍摄日期】 | 读取文件的 EXIF 拍摄日期 |
| 3 | 【修改日期】 | 读取文件修改日期 |
| 4 | 【创建日期】 | 读取文件创建日期 |

【文件名中的日期】的匹配规则：

- 匹配格式1（先验）：`yyyy-mm-dd`，例如 `2020-02-02`。
- 匹配格式2（先验）：`yyyymmdd`，例如 `20200202`。
- 先验条件：匹配位置必须是字符串起始，或前一个字符不是数字，保障不会从更长数字串的中间开始匹配。
- 不要求匹配后边界：日期后面可能是时间、文件名或连接符，不能据此拒绝。
- 年份 `yyyy` 的允许范围：【最早起始年份】至当前年份（含边界）。
- 在【文件名中的日期】内部，匹配到任意一个符合规则的日期后即停止，不再继续查找其他日期。
- 两种格式的尝试顺序、同一格式多次出现时的取舍，按原文“按顺序获取任意一个即停止”执行；仍作为待确认项记录（见第10章）。

### 5.3 主界面与实时预览

窗口包含两个部分：

1. **配置框**：用于配置目标路径名和文件名的生成规则。
2. **表格**：用于预览源路径与目标路径。

表格要求：

| 列 | 内容 |
|---|---|
| 第1列 | 源路径名 |
| 第2列 | 目标路径名/文件名 |

交互要求：

- 鼠标悬浮在表格行上时，显示该文件的各种属性信息。
- 提供【实时刷新】开关：
  - 开启时，配置变更后目标路径名/文件名实时刷新。
  - 关闭时，配置变更不立即刷新目标路径；用户点击【预览】按钮手动刷新。
- 表格仅用于预览，不执行最终处理。

### 5.4 配置项

#### 配置0：过滤器

- 位于根路径卡片上方。
- 功能与 `https://github.com/lj-k/APP_FileSettle` 保持同步；当前可访问版本/仓库内容见第12章说明。
- 决策模式支持四种：
  - 【跳过】：命中扩展名列表的文件跳过；未命中的文件按模板执行（同目录为重命名，跨目录为复制）。
  - 【复制】：仅命中扩展名列表的文件复制到目标路径；未命中文件跳过。
  - 【移动】：仅命中扩展名列表的文件移动到目标路径；未命中文件跳过。
  - 【重命名】：仅命中扩展名列表的文件重命名；未命中文件跳过。
- 扩展名列表为空表示不过滤，所有文件都参与决策。
- 决策为【重命名】时，目标路径和文件名编辑器的默认内容为：
  `【根路径】/【源文件名】-【校验码】.【扩展名】`
  - 仅当模板仍是默认模板时随模式切换自动替换，避免覆盖用户手工修改。
- 动作自动匹配规则：
  - 决策为【重命名】且目标目录与源目录相同 → 动作【重命名】。
  - 决策为【重命名】但模板加入中间文件夹，导致目标目录变化 → 动作【复制】。
  - 决策为【复制】→ 动作【复制】；决策为【移动】→ 动作【移动】。
  - 决策为【跳过】且未命中排除列表时，按目标目录是否变化得到【重命名】或【复制】。
- 扩展名列表支持分隔符、通配符和空列表。
- 提供动作词典变量【扩展名预设】，用于保存和载入扩展名列表。
- 载入扩展名预设时可选：
  - 覆盖现有扩展名列表。
  - 追加到现有扩展名列表（append）。
- 保存预设和扩展名预设时，应通过 `winContext.Context.SetVarValue` 直接更新对应的 Quicker 动作变量，不需要在自定义窗口后追加变量赋值步骤；窗口关闭时再由数据映射兜底写回。
- Quicker 把“保存为状态”的嵌套词典读回时可能是 JSON 文本，窗口启动时必须先把 JSON 文本还原为词典，再载入预设。

#### 配置1：根路径

- 默认【当前文件夹】。
- 可选择【当前文件夹】或【其他文件夹】。
- 当用户选择【其他文件夹】时，跳出文件夹选择器。
- 【当前文件夹】明确指每个源文件所在目录。

#### 配置2：最早起始年份

- 默认值为 2000。
- 当该配置变更时，重新获取【文件名中的日期】。

#### 配置3：日期

**配置3.1：日期来源**

从以下四项中四选一，默认【文件名中的日期】：

- 【文件名中的日期】
- 【exif拍摄日期】
- 【修改日期】
- 【创建日期】

选中的日期来源用于模板中的【日期yyyy】、【日期mm】、【日期dd】。

**配置3.2：缺失递补**

- 取消“是否启用缺失递补”开关和“递补关闭时缺失值”设置。
- 递补1~5在同一行展示。
- 每个递补下拉均可选择：
  - 【文件名中的日期】
  - 【exif拍摄日期】
  - 【修改日期】
  - 【创建日期】
  - 【空值】
  - 【自定义】
  - 【跳过】
- 递补5用于最终兜底，默认【空值】。
- 【空值】：三个日期胶囊【日期yyyy】【日期mm】【日期dd】都输出空值，并停止继续递补。
- 【自定义】：使用统一的自定义值替换三个日期胶囊，并停止继续递补。
- 【跳过】：命中该项时不再处理该文件，也不输出该文件。
- 主日期来源缺失后，按递补1→5顺序处理；日期来源可用则采用，遇到空值/自定义/跳过则立即结束。

**配置3.3：文件名日期与EXIF冲突**

- 开关名称：文件名日期与EXIF不一致时用EXIF。
- 默认关闭。
- 开启后，若同时满足：
  - 文件名中匹配到日期；
  - 获得EXIF拍摄日期；
  - 两者日历日期（yyyy-MM-dd）不同；
  - 且生效日期本来会采用文件名日期（主选为文件名日期，或递补轮到文件名日期）；
  则输出EXIF拍摄日期，生效来源显示为EXIF拍摄日期。
- 若两者的日历日期相同，即使时间部分不同，也视为不冲突，仍采用文件名日期。
- 若主选为修改日期、创建日期或EXIF拍摄日期，该开关不覆盖主选结果。
- 开关状态需要写入预设词典，载入预设时恢复。

#### 配置4：校验码

包含以下子配置：

| 子配置 | 取值/说明 |
|---|---|
| 【校验算法】 | CRC32、BLAKE3、MD5、SHA-256 |
| 【校验位数】 | 1 至该算法的最高位数；位数为16进制位数 |
| 【校验码前缀】 | 用户可配置 |
| 【校验码后缀】 | 用户可配置 |

校验码显示格式：

- 【校验码前缀】默认为 `[`，【校验码后缀】默认为 `]`。
- 输出结构为：`前缀 + 算法标识[_位数] + "-" + 校验码 + 后缀`。
- 当校验位数等于该算法的默认最高位数时，算法标识不显示位数：`[CRC32-7f7f7f7f]`。
- 当校验位数小于默认最高位数时，算法标识追加 `_位数`：`[CRC32_4-7f7f]`，其中 `4` 表示16进制位数，`7f7f` 为截取后的校验码。
- 校验码截取取高位；默认完整长度。
- 默认最高位数按算法标准输出长度换算：
  - CRC32：8 位16进制
  - BLAKE3：64 位16进制（32字节默认输出）
  - MD5：32 位16进制
  - SHA-256：64 位16进制

校验码例1：

```text
【校验算法】= CRC32
【校验位数】= 8
【校验码前缀】= [
【校验码后缀】= ]
输出 = [CRC32-7f7f7f7f]
```

#### 配置5：目标路径和文件名编辑器

- 编辑器中可点击胶囊（模板变量按钮），在当前光标位置插入胶囊。
- 需要支持以下胶囊：

| 胶囊 | 含义 |
|---|---|
| 【日期yyyy】 | 四位年份 |
| 【日期mm】 | 两位月份 |
| 【日期dd】 | 两位日期 |
| 【根路径】 | 根据【根路径】配置得到的根目录 |
| 【源文件名】 | 源文件名，不带扩展名 |
| 【扩展名】 | 文件扩展名 |
| 【校验码】 | 按校验码配置生成的校验码文本 |

- 胶囊插入位置必须为目标路径编辑框的当前光标位置。
- 日期胶囊的值来自【配置3】确定的日期；日期缺失时按【配置3.2】处理。
- 默认模板为：

```text
【根路径】/【日期yyyy】.【日期mm】/aaa/bbb/【源文件名】-【校验码】.【扩展名】
```

- 输出路径分隔符统一为 Windows 反斜杠 `\`。

### 5.5 示例

原文示例1：

```text
输入路径为：C://A/B/C/D.TXT
目标路径和文件名编辑器内容（默认）：【根路径】/【日期yyyy】.【日期mm】/aaa/bbb/【源文件名】-【校验码】.【扩展名】
配置1【根路径】=当前文件夹，【校验码】=（[CRC32_4-7f7f]）
重命名后的内容为：C://A/B/C/2020.06/aaa/bbb/D-[CRC32_4-7f7f].TXT
```

示例结果中的 `2020.06` 对应模板里的 `【日期yyyy】.【日期mm】/` 层级；输出实际使用 Windows 反斜杠。

### 5.6 预设载入与保存

- 窗口最上方提供【载入预设】和【保存预设】两个按钮。
- 【载入预设】：点击后展示预设下拉框；选择某个预设后载入其全部配置。
- 【保存预设】：点击后要求输入预设名称并保存当前全部配置参数。
- 若输入的名称与现有预设冲突：
  - 提示是否覆盖。
  - 显示发生变更的配置项目（旧值 → 新值）。
  - 用户确认后才覆盖。
- 预设输出为 Quicker 的词典格式，对应词典【批量重命名器预设】；词典支持多套命名预设。
- 需保存的配置参数至少包括：
  - 过滤器扩展名列表、决策模式（跳过/复制/移动/重命名）
  - 根路径模式与根路径值
  - 最早起始年份
  - 日期来源
  - 文件名日期与EXIF不一致时用EXIF开关
  - 递补1~5（日期来源/空值/自定义/跳过）与统一自定义文本
  - 实时刷新开关
  - 执行并行数量（1~8）
  - 执行后校验开关
  - 校验算法
  - 校验位数
  - 校验码前缀
  - 校验码后缀
  - 目标路径和文件名编辑器中的模板内容
- 【批量重命名器预设】词典统一为扁平结构：
  - 键：预设名称；
  - 值：该预设完整配置的JSON字符串。
  - 示例：`{"默认":"{\"rootMode\":\"current\",...}","图片截屏":"{...}"}`。
- 载入时按选中的键读取value，解析JSON为配置词典，再应用到界面；不依赖嵌套的`presets`结构。
- 兼容旧结构`{presetVersion, presets:{...}}`和更旧单预设词典，读取时自动迁移。
- 旧结构识别不得依赖`presetVersion`键：只要`presets`的值不是单套配置，就按旧嵌套结构读取；预设名称恰好为`template`、`presets`等键时不得误判。
- 【扩展名预设】与【批量重命名器预设】使用同一套扁平结构：键为预设名称，值为扩展名列表字符串，例如`{"图片":"jpg;png","文档":"doc;docx"}`；同样兼容旧嵌套结构。
- 数据映射可能把未赋值的词典变量传成空词典或空字符串；窗口启动时若映射值为空，应回退通过`GetVarValue`读取动作变量，避免已保存预设显示为空。
- 保存同名预设且配置没有变化时，也应回写一次扁平结构，顺带完成旧结构迁移。
- 预设必须覆盖第5.6节列出的全部配置参数；`BuildPresetDictionary`与`CreateDefaultConfig`的键集合必须一致。
- 生成输出时若尚未保存任何预设，应至少输出当前配置作为“默认”预设。
- 保存预设时应通过 `winContext.Context.SetVarValue` 直接更新 Quicker 动作变量【批量重命名器预设】，不需要在自定义窗口后追加变量赋值步骤；窗口关闭时数据映射继续作为兜底。
- 窗口启动时必须从数据映射读取【批量重命名器预设】与【扩展名预设】；若映射缺失，应尝试通过 `GetVarValue` 读取动作变量。
- 仅把 Quicker 变量设置为“保存为状态”不等于数据映射；必须同时配置 `preset:{批量重命名器预设}` 与 `extensionPresets:{扩展名预设}`。
- “保存为状态”的预设词典可能以 JSON 文本读回；加载前必须解析为扁平词典，否则会误判为“没有已保存的预设”。
- 【完成】/【执行】时应回写当前已保存的预设库与扩展名预设库，确保窗口关闭后动作变量得到最新结构。
- 提供独立动作词典变量【扩展名预设】，用于保存和载入扩展名列表；载入时可选覆盖现有或追加（append）现有。
- 预设的存储位置、命名方式及词典键名结构见第10章待确认事项。

### 5.7 路径校验与错误提示

目标路径和文件名编辑器生成的路径必须通过跨平台校验：

- 非法字符取 Linux、Windows、macOS、Android 的并集，至少包括：
  - Windows：`< > : " / \ | ? *` 及 ASCII 控制字符。
  - macOS：`:`、`/`。
  - Linux：`/`、NUL。
  - Android：`/`、NUL。
- 其他非法路径问题：
  - 空路径、空路径段。
  - `.`、`..` 目录段。
  - 路径段以空格或点结尾。
  - Windows 保留设备名（CON、PRN、AUX、NUL、COM1–COM9、LPT1–LPT9 等）。
  - 路径段超长、总路径超长。
  - 非绝对路径、缺少文件名、UNC 路径缺少服务器/共享/文件名。
- 发现非法路径时：
  - 在窗口上方以红字显示错误提示。
  - 使用红底高亮表格中的异常行。
  - 校验结果需能指出具体的非法字符或非法路径问题。

### 5.10 文件传输性能与RAS

#### 性能策略

- Windows 下优先使用系统原生 `CopyFileEx`（保留文件属性/时间戳、支持进度回调与取消）；不可用时回退到托管流式复制。
- 托管流式复制按目标驱动器类型与文件大小选择缓冲：
  - 网络/UNC：256 KiB。
  - 光驱：64 KiB。
  - U盘/外置可移动盘：默认1 MiB；文件≥512 MiB时2 MiB。
  - 固定盘/未知盘：默认1 MiB；文件≥1 GiB时4 MiB。
  - SSD与HDD无法通过标准 `DriveInfo` 可靠区分，统一按固定盘策略；大文件使用4 MiB。
- 固定盘且文件≥64 MiB时预分配目标文件长度，减少碎片与元数据扩展。
- 同卷移动/重命名直接 `File.Move`；跨卷移动采用“复制→校验→删除源文件”，复制阶段使用上述策略。
- 复制先写入同目录临时文件（`.qk-随机.tmp`），成功后再原子改名到目标，避免留下半成品目标。
- 复制完成后保留源文件的创建时间、修改时间与属性。
- 进度回调按已传输字节增量上报，执行状态中的传输速度可随复制实时更新。

#### RAS策略

- 目标已存在：拒绝覆盖并报错。
- 源文件不存在、路径无效、目标目录不可写：逐项报错，不中断其他项目。
- 复制/移动前检查目标磁盘可用空间（网络路径无法可靠获取时跳过检查）。
- 复制前后校验源文件长度与最后修改时间；复制期间源文件变化则删除临时文件并报错。
- 对共享冲突、锁定、网络超时/断开、设备未就绪等瞬态错误最多重试3次，退避200/400/800 ms；每次重试前清理临时文件，并在失败时回滚已上报的进度。
- 复制/移动后校验失败：复制动作删除目标文件；跨卷移动在删除源文件前校验，失败时删除目标并保留源文件。
- 可移动盘复制完成后执行落盘刷新；网络路径使用普通刷新以降低延迟。
- 执行中取消/关闭：不再领取新项目，已开始项目完成；执行线程全部退出后再关闭窗口。
- 错误信息转换为可读原因（占用、拒绝访问、空间不足、网络路径不可用、超时等）。

#### 场景覆盖

| 场景 | 策略 |
|---|---|
| 驱动器内复制 | 原生复制；临时文件+改名；进度/校验 |
| 驱动器内移动/重命名 | `File.Move`，失败重试 |
| 跨驱动器/跨盘复制 | 目标盘空间检查、原生/缓冲复制、临时文件 |
| 跨驱动器/跨盘移动 | 复制→校验→删除源；删除失败回滚目标 |
| 跨网络/远程/UNC | 256 KiB缓冲、网络错误重试、跳过不可靠空间检查 |
| U盘/外置盘 | 1~2 MiB缓冲、落盘刷新、校验 |
| SSD | 固定盘策略，大文件4 MiB缓冲 |
| HDD | 固定盘策略，预分配+顺序扫描提示，大文件4 MiB缓冲 |

### 5.11 双交付方案与完成按钮

- 方案1：仅重命名不执行
  - 隐藏执行配置框、【执行文件】按钮与【完成】按钮。
  - 原【生成输出】按钮显示为【执行】，点击后关闭窗口并继续 Quicker 后续动作；不会修改文件。
  - 输出三个非跳过列表：原路径、目标路径、动作。
  - 数据映射包含 `origPaths`、`targetPaths`、`actions`。
- 方案2：执行不输出列表
  - 保留执行配置框与【执行】按钮。
  - 隐藏【生成输出】按钮，保留【取消】【完成】。

### 5.12 交互窗口与执行性能优化

#### 交互窗口性能

- 扫描结果按批次（50 项）加入表格；表格启用行虚拟化与容器回收，未显示的行走复用容器，不参与布局。
- EXIF 拍摄日期只读取图像元数据，不解码像素（`BitmapCacheOption.None`）；扫描照片时不再为每张图加载完整位图。
- 实时预览沿用 250 ms 防抖；关闭【实时刷新】时配置变更不触发目标路径重算。
- 模板是否包含【校验码】的检测结果按模板字符串缓存；模板未变化时，逐行构建悬浮详情不再重复执行正则。
- 状态栏统计（就绪/异常/校验码计算中/过滤或日期跳过）合并为一次遍历，避免同一刷新内多次全表扫描。
- 批量刷新日期使用四值重载，不再为每一行构造 `Dictionary`。
- 校验码计算进度按约 120 ms 节流上报；计算完成时强制上报最终进度。
- 目标路径存在性检查仍在预览重算时同步执行，以保证“目标已存在”提示及时准确。

#### 执行性能

- 执行行状态合并刷新：工作线程只更新对应行数据并置脏标记，界面由执行定时器统一执行一次表格刷新（约 200 ms 周期），避免每个文件完成都触发全表刷新。
- 同卷移动/重命名只改变目录项，文件内容不变；开启执行后校验时，同卷移动不再重新读取源文件与目标文件计算内容校验码；若模板包含【校验码】，仍校验目标文件名中的校验码标记。
- 复制与跨卷移动仍执行完整内容校验（源校验码与目标校验码比较）。
- 执行开始时对算法、位数、前后缀、校验开关、模板是否含【校验码】做配置快照，逐文件执行不再重复读取配置词典或执行正则。
- 执行会话内缓存已确认/已创建的目标目录，每个唯一目录只做一次存在性检查与创建。
- BLAKE3 压缩使用线程内复用的临时缓冲区，消除每个 64 字节块的数组分配；哈希仍按块流式计算，不将整文件读入内存。
- 复制/移动的缓冲、临时文件、重试、空间检查与回滚策略保持第 5.10 节不变。

#### 约束与兼容

- 不改变预览与执行的输出契约、动作判定、RAS 策略和双交付方案差异。
- 同卷移动的校验语义调整为“文件名校验码校验 + 内容不变的事实推定”，跨卷移动/复制仍为“内容哈希校验”。
- 预览阶段仍不产生任何文件系统写操作。

## 7. 验收标准

以下条目用于验收，待确认事项确认后需补充对应细则：

1. 输入列表中的文件夹被跳过，不进入预览表格及输出列表。
2. 能从文件名中识别 `yyyy-mm-dd` 与 `yyyymmdd` 两种日期格式，遵守前边界、年份范围；不因后边界拒绝日期。
3. 【最早起始年份】变更后，【文件名中的日期】重新计算。
4. 四类日期均可获取，日期来源默认【文件名中的日期】，可四选一。
5. 日期递补1~5在同一行；每项可选四类日期、空值、自定义、跳过；递补5默认空值；空值下三个日期胶囊都为空；跳过文件不处理、不输出。
6. 日期卡片提供“文件名日期与EXIF不一致时用EXIF”开关；开启后，文件名日期与EXIF日历日期不同且生效日期本来会用文件名日期时，改用EXIF拍摄日期。
7. 【实时刷新】开启时配置变更即时刷新；关闭时点击【预览】按钮手动刷新。
8. 表格展示动作、源路径名、目标路径名/文件名三列；行悬浮显示属性。
9. 【根路径】默认当前文件夹（每个源文件所在目录），支持其他文件夹并弹出选择器。
10. 校验码支持 CRC32、BLAKE3、MD5、SHA-256；默认前后缀为 `[`、`]`，位数范围为 1 至算法最高位数，截取取高位。
11. 编辑器支持七种胶囊，并能在光标位置插入。
12. 卡片标题在左侧竖排区域，说明在标题悬浮显示；过滤器在根路径上方；根路径/日期/校验码相关胶囊在同行右侧；所有胶囊在右列；模板输入框在左、其余胶囊在右。
13. 默认模板包含 `aaa/bbb` 层级；重命名模式默认模板为 `【根路径】/【源文件名】-【校验码】.【扩展名】`；输出路径分隔符统一为 Windows 反斜杠。
14. 路径校验覆盖四个平台的非法字符并提示具体问题；异常时窗口上方红字提示，表格异常行红底高亮。
15. 预设按钮位于窗口顶部；载入显示预设下拉框；保存要求输入名称；同名冲突显示变更项目并询问覆盖；保存时尽量实时更新动作变量。
16. 所有配置项、胶囊、预设/预览/输出/执行按钮均有悬浮说明，覆盖含义、结果和后果。
17. 【载入】/【保存】可完整往返全部配置参数（含过滤器、执行并行与校验）；预设词典为“名称→JSON配置”扁平结构，载入时解析value还原全部配置；旧版嵌套/单预设结构可自动迁移。
18. 提供【扩展名预设】词典，支持扩展名列表保存；载入时可选择覆盖或追加。
19. 窗口输出两个路径列表、一个动作列表和一个预设词典；三者长度一致、序号对应同一文件；只有点击【执行】后才修改文件。
20. 示例1的结果包含 `2020.06` 日期层级，且与模板组合规则一致。
21. 过滤器决策模式支持跳过、复制、移动、重命名；重命名模式在模板加入中间文件夹时动作显示为复制。
22. 展示列表下方有执行配置框与执行按钮；并行数量1~8；执行后校验可开关。
23. 执行前检查源路径；目标目录不存在时自动创建；目标文件已存在时报错且不覆盖。
24. 复制/移动后可重新计算目标校验码，并与源校验码及文件名中的校验码标记核对。
25. 执行状态显示总数、完成、错误、传输速度、执行速度；成功行绿底、失败行红底并可悬浮查看原因。
26. 复制/移动按驱动器类型选择缓冲策略；Windows 优先使用系统原生复制，失败可回退托管流复制。
27. 跨卷移动按“复制→校验→删除源”执行；删除源失败时回滚目标。
28. 复制使用临时文件+改名，失败或取消后不留下半成品目标。
29. 瞬态错误最多重试3次，退避200/400/800 ms；错误原因可读。
30. 复制前检查目标空间与源文件稳定性；复制期间源文件变化应报错。
31. 复制完成后保留源文件时间戳与属性。
32. 展示列表成功/失败/计算中/跳过状态通过行背景色表达，不使用字体颜色。
33. 方案1没有【完成】按钮；原【生成输出】显示为【执行】，点击关闭窗口并继续 Quicker 后续步骤。
34. 方案1保留决策模式与动作列，输出三个非跳过列表（原路径、目标路径、动作），三者逐项配对。
35. 方案2无【生成输出】按钮，保留【完成】；不初始化/不写入任何路径列表或动作列表变量。
36. 两套交付方案共享源码、构建脚本与文档，版本同步更新。
37. 窗口启动时读取两个预设变量；仅设置“保存为状态”但未配置数据映射时，应能识别为未映射并在文档中明确说明。
38. 保存预设时直接写回动作变量，不要求用户在自定义窗口后追加变量赋值步骤。
39. 窗口启动时能识别“保存为状态”读回的 JSON 文本，并还原为词典；完成/执行时回写预设库与扩展名预设库，下一次启动可载入上次保存的预设。
40. 扫描含 EXIF 的图片时只读取元数据、不解码像素；万级文件下列表滚动与配置刷新保持可交互。
41. 执行期间行状态更新合并刷新，不因单个文件完成触发全表刷新；执行状态与进度仍持续更新。
42. 同卷移动开启执行后校验时，不重新读取文件内容计算哈希；跨卷移动与复制仍执行内容校验。
43. 模板修改后，校验码检测缓存自动失效；状态栏计数与实际行状态一致。

## 8. 非功能要求

| 类别 | 要求 |
|---|---|
| 平台兼容 | 必须作为 Quicker【自定义窗口】动作运行，符合第4章约束 |
| 数据安全 | 预览阶段不得执行重命名、移动、复制、删除等文件系统写操作；执行阶段不覆盖已存在目标 |
| 配置完整性 | 预设需保存第5.6节列出的全部配置参数 |
| 实时性 | 实时刷新开启时配置变更即时刷新；关闭时由【预览】按钮手动刷新 |
| 路径安全 | 目标路径需通过 Linux/Windows/macOS/Android 非法字符并集校验 |
| 执行安全 | 执行前检查源路径；自动创建目标目录；目标已存在时报错；跨卷移动先复制校验后删除源文件 |
| 传输性能 | Windows 优先原生复制；按驱动器类型/文件大小选择缓冲；同卷移动直接移动；进度实时上报 |
| 传输RAS | 临时文件+原子改名；瞬态错误重试；空间/稳定性检查；失败清理；时间戳/属性保留 |
| 界面性能 | 扫描与预览刷新不阻塞交互；EXIF只读元数据；批量刷新合并界面更新；校验码检测按模板缓存 |
| 执行性能 | 执行行状态合并刷新；同卷移动免内容重算；配置快照与目录缓存；BLAKE3块处理复用缓冲区 |
| 可维护性 | 模板、预设、校验码、执行动作规则应保持结构清晰，便于后续扩展算法与胶囊 |

## 9. 需求边界

- 本需求定义配置、预览、输出与执行；执行仅包含复制、移动、重命名。
- 本需求不定义删除、覆盖已有目标文件、自动改名等策略；目标已存在时当前按错误处理。
- 本需求不定义执行失败后的自动回滚（跨卷移动失败会尽量删除已复制目标，其他情况保留现状）。
- 多套命名预设的管理界面仅包含载入下拉与命名保存。

以上未定义内容如需实现，应作为新增需求另行确认。

## 14. 第一性原理代码评审要求（0.0.16）

以“输入→解析→渲染→校验→执行→输出”的最小事实链为基准，不依赖历史实现推断，逐层复核并满足：

1. 鲁棒性：所有外部输入（路径、预设JSON、配置值、文件状态）在边界处校验；错误信息面向用户且可定位；取消、删除、权限、空间不足、目标已存在等异常路径均有确定结果。
2. 效率：批量路径避免逐文件重复分配与重复解析；I/O缓冲在线程内复用；界面刷新合并，扫描、哈希、执行不阻塞UI。
3. 代码复用：同一规则只保留一个实现（日期别名、位数钳制、徽标组装、模板词典、配置吸收、日期刷新、变量上下文遍历、预设键表），避免多处逻辑漂移。
4. 测试完整性：除常规路径外，覆盖空值、负数、越界、重复、大小写、别名、深层嵌套、并发取消、目标冲突、UNC/盘符等corner case，并在交付前全部通过。

特别说明（0.0.17）：OneDrive等云占位文件的内容不在本地，读取EXIF需要先下载文件内容。本版在扫描时识别离线/按需回填属性，云端占位直接跳过EXIF内容读取，因此这类文件的“EXIF拍摄日期”为空，日期按递补链回退；如确需EXIF，请先在资源管理器中“始终保留在此设备上”。输入路径的存在性校验从UI线程移到扫描线程，列表顺序仍按输入顺序发布；目标路径布局在超过阈值时后台并行计算，配置变化会使旧计算作废，不会把旧结果写回列表。

## 15. 并发扫描与调度要求（0.0.17）

1. 扫描阶段按固定大小分块，由原子计数器分配任务；每个分块只被一个线程领取，每个结果只写入自己的槽位，线程之间不共享可变集合。
2. 扫描结果由独立发布线程按输入顺序合并后交给UI线程，保证预览、输出与执行顺序稳定。
3. 文件属性读取、文件名日期计算、目标路径与文件名生成、目标存在性检查均允许并行；UI线程只做结果应用与控件刷新。
4. 所有后台计算携带代际号；配置变化、重新扫描、窗口关闭时递增代际号，旧任务在下一个任务点停止并丢弃结果，禁止把过期布局写回界面。
5. 并发数有上限：扫描受`ScanMaxWorkers`限制，CPU计算不超过8线程，I/O检查不超过扫描线程上限，避免线程抢占与内存膨胀。
6. 云端占位文件不得为了读取EXIF而触发内容下载；该行为必须在详情中可见。

特别说明（0.0.18）：性能栏的瓶颈判断是启发式，不是精确剖析。处理样本不少于64个且耗时不少于50ms时，按“实际计算线程可用核心数”折算CPU占用：≥65%判为CPU，≤30%判为I/O，其间判为CPU/I/O混合；样本或耗时不足时显示“样本小”。I/O包含磁盘、网络与云端回填等待；CPU占用为进程级，可能包含UI与哈希线程，因此显示为“CPU占用”而非单线程占用。速度按启动到完成的墙钟时间计算，包含排队与线程创建开销。

## 16. 性能显示要求（0.0.18）

1. 底部固定显示两行性能信息：属性读取、目标路径计算。
2. 每行显示处理速度（个/秒）、样本个数、总耗时与瓶颈类型。
3. 属性读取额外显示平均每个文件的读取耗时。
4. 显示实际启动的线程数量：扫描显示工作线程数与发布线程数；目标路径显示计算线程数与存在性检查线程数；未另开线程时显示“主线程内联”。
5. 瓶颈至少区分CPU、I/O、CPU/I/O混合、样本小与未知。
6. 扫描进行中显示“进行中”，实时预览关闭导致目标路径待刷新时显示“待刷新”。
7. 性能采集不得引入明显开销：每阶段只读取两次时间戳与两次进程CPU时间。

特别说明（0.0.19）：目标冲突比较顺序为“文件大小→默认校验码（CRC32）→逐字节二进制”，CRC32仅用于快速预筛，最终结论以二进制比较为准。云端占位文件不读取内容，避免为了去重触发下载，直接按冲突加序号；目录、无法读取或无权限比较时同样加序号，绝不覆盖或删除。相同内容的“移动/重命名”会先执行动作“删除原文件”，真正删除前会在执行线程再次比较源/目标内容，目标已变化或无法确认时取消删除。批内多个文件得到同一目标路径时，从第二个起自动加序号，不再作为异常。预览筛选与排序只影响显示，不改变 `_files` 的执行与输出顺序。

## 17. 目标冲突处理与预览筛选排序（0.0.19）

1. 目标文件已存在时，依次比较大小、默认校验码（CRC32）、二进制内容。
2. 比较结果相同：
   - 最终动作为“复制”时，动作改为“跳过”，不计入执行与输出；
   - 最终动作为“移动”或“重命名”时，动作改为“删除原文件”，仅删除源文件，目标文件保持不变。
3. 比较结果不同或无法比较（云端占位、目录、权限错误）时，在文件名后追加 ` (n)`，n 从1开始递增，直到目标在磁盘与当前批次中都未被占用。
4. 序号上限为9999；超过上限时该项标记为“目标冲突”异常，不执行。
5. 预览表新增“状态”“异常状态”“执行结果”列。
6. 点击“动作/状态/源路径名/目标路径名/异常状态/执行结果”表头可升序/降序排序；扫描期间暂不排序。
7. 预览上方提供文本筛选（源路径、目标路径、文件名、异常、执行结果）与状态筛选（全部/就绪/异常/跳过/校验中/执行成功/执行失败）。
8. 筛选和排序均为显示层行为，不改变执行顺序、输出列表顺序与内容。
